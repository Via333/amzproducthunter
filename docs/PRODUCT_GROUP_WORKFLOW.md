# 产品组、形态与研究范围

更新：2026-09-06。此文档记录用户确认的选品顺序。

## 判断单位

1. 类目和关键词是发现商品的入口，不是产品身份，也不是机会单位。
2. 先读标题判断核心功能、使用场景和替代关系，归入同用途产品组。
3. 组内再按材质、结构、使用方式拆形态；标题不够明确时，用主图、详情补证据。
4. 单件、多件同款、多尺寸组合属于同产品组。套装数量、规格和附带配件用于组内比较，不因 set/kit/pack 单词另建产品身份。
5. 混合套装按核心用途和实际组成判断：量杯加倒酒嘴仍是量杯方案，摇酒器加量杯等完整调酒套装与单纯计量工具用途不完全相同，不能因都含 jigger 就混作同款。
6. 形态机会各自独立验证；同一个产品组可以同时有多种形态值得研究。
7. 页面上层按使用场景组织：例如“调酒器具”下并列“调酒量杯”和“综合调酒工具套装”。来源 Jiggers/Bar Sets 不是两个互斥市场；同用途商品跨来源合并，但同场景不等于同款或直接竞品。

## 证据顺序

- 标题中的明确用途优先于数据源 product_type；类目路径只作背景。
- 当前自动判断使用可测试的标题规则，不声称能理解所有商品语义。
- 标题品名统一由 `title_product_names.py` 与 `config/title_product_names.json` 提取：仅对品名词表做单复数归一，支持同义名称；先识别主体子句，再区分整机、附带配件和兼容对象。供应商 product_type 或来源类目不能单独证明产品用途。
- 同名不同用途、标题只剩型号、缺少主体、未覆盖的名称仍保留待确认，不强行套用来源标签。用途确定但关键规格不明进入自己的产品组并标为“形态待确认”，不把用途组当成已核实的同款形态。
- 同形态的规格证据不齐时取保守状态，不由第一条商品记录决定是否评分。已知整机继续执行产品排除；垃圾处理机与它的无源密封圈、防溅片、法兰分别判断。
- 用途不明标记“用途待确认”；用途已知但材质/结构不明标记“形态待确认”。两者不评分、不自动入池，不等于市场不可做。
- 先剔除具体商品的已有硬风险，再计算形态的有效样本指标。
- 竞争墙和品牌集中度按同用途组统计，不能用通用类目里另一类产品的头部数据直接否定本组。
- 保留类目原始指标作背景，但必须区分其与产品组的统计口径。

## 深度研究

选中一个 ASIN/形态后，研究范围回到其所在类目 Top100 或核心关键词产品结果：

- 遍历源数据中的主要用途，筛出同用途产品及可替代方案，不仅查选中的形态。
- 按 ASIN 去重，记录类目、关键词来源及原始数据时间；关键词流量表不算关键词产品遍历证据。
- 展示各形态样本量、总月销、单品月销中位、组内销量份额、价格、评论和新品达标情况。
- 单独展示每种形态的套装数量分布，不把套装月销乘件数当作单品需求，不混淆整套价与单件价。
- 评论预算先覆盖目标形态和主要替代形态，避免全部用在同一种形态上；不把同类目但不同用途的商品当作直接竞品。
- 切入口是待验证假设：新品有销量、某组合供给少、评价暴露痛点等，仍需实际需求、同款成本和风险证据支持。
- 数据覆盖有限时明确写样本范围，不能说扫描了整个市场或已遍历所有形态。

## 当前实现

- 分类入口：`product_taxonomy.py`、`product_family.py`；调酒量杯按标题用途和结构重分，豆腐压制器/沥水模具作为同用途的不同形态。
- 自动验证：`category_shape_validation.py`；按同用途组计算竞争指标，形态分别评估；未确认分类不因低分排除。
- 研究全景：`research_landscape.py` 从现有类目原始报告、明确记录的 MCP 关键词产品结果和研究样本合并复核，输出 `product_landscape.json`。
- 研究页面展示“同用途产品全景”，已有研究样本及其人工结论保留，不冒充本次重新核验结论。
- 分组重算使用现有缓存，不新增 Sorftime 请求；重新分析日期不表示原始市场数据也已刷新。
- 图片单独补全：`research_images.py --asin ASIN --max-calls 100`（Python需有Pillow），通过 `product_detail.main_image` 获取图片地址，不爬Amazon页面。先复用同ASIN本地图片和详情缓存，失败项保留状态，显式 `--retry-failed` 才重试。`image_manifest.json` 记录进度和调用数，网页构建不触发采集。
- 图库展示当前同用途组的全部ASIN，支持按当前形态筛选，不再只取前36个；商品数量、已有图和缺图分别计数。图片补全不改动旧研究的销量、价格或结论。
- 食品接触、大件、易碎、专利、季节性、利润等原有约束保持独立；重新归组不自动放行。
- 网页当前验证由 `product_market_validation.py` 从同一轮原始 Top100 缓存跨来源归组。ASIN 去重后调用共享验证器重算，保留每个形态的来源列表，不相加原类目销量/评论中位数。一个来源发现的硬风险不能因为切换来源而消失。
- 同 ASIN 数值冲突按明确标题身份、固定来源 ID 顺序取一份完整记录，并显示冲突数，不挑最大销量。用途冲突转待确认；不得跨扫描批次混入旧价格/销量。
- 目前场景上层显式支持“调酒器具”的量杯与综合套装；其他已识别用途以自身产品组展示，未确认用途独立保留，不根据父类目强行归组。
- 来源类目 CSV、扫描覆盖和机会档案保留原始来源口径；网页跨来源比较是派生视图，不会因重建页面写入或改写历史机会档案。不能把网页重算描述为已迁移全部历史市场数据。
- 2026-09-06 标题品名修订只用同轮缓存重建网页当前验证视图，未重采 Sorftime、未覆盖原始扫描或旧研究结论。新启动的分类与研究入口使用修订后的同一套标题识别逻辑。

## 维护要求

### 近半年新品起量核验

每次单品研究在同用途产品全景之后追加一层归因，不替代原有近18个月的粗筛指标：

1. 按分析日回溯六个日历月（含边界），选上架日在窗口内、快照月销严格大于300的ASIN；上架或月销缺失不能填零或推断达标。这里只覆盖已有类目/关键词样本，不声称全市场。
2. 先查ASIN/父子体、目标子款销量档位和评论日期/变体属性，再判断独立新品是否起量。`product_variations.SalesAmount` 是最近15天内捕获的子款公开销量，不是销售额，也不是精确月销量；-1是未更新，不能算零。共享评论或链接趋势不能全部归因到新子款。
3. 归因分别核对品牌老产品与品牌搜索基础、可验证的功能改进、同规格同件数价格/促销、评论痛点和流量来源。宽泛同形态不代表同规格，例如厨房水槽滤网不能直接与浴室小口径配件比价。没查到品牌证据不等于品牌弱；新功能声明不等于独有创新；同时降价与增长不等于已证明因果。
4. 剔除当月趋势，不把上架首个不完整月当成熟月份，也不把新品爬坡当季节性。标出最新返回评论日期，避免把陈旧混合变体评论当近期反馈。广告、站外、促销占比未取得时明确未知。
5. 输出产品级驱动判断、置信限制及形态级待核切入口。品牌依赖型不能当普通卖家可复制证据；低价型需完整利润；差异化型需买家价值、知识产权及成本。未证实可复制不等于淘汰整个形态，也不覆盖既有硬风险排除。

`refresh_product_research.py --asin ASIN` 默认追加最多15次MCP调用。`--new-entrant-max-calls 0`只读缓存；已有档案重建不联网。独立补证据命令：

```sh
python3 new_entrant_research.py --asin ASIN --collect --max-calls 15
python3 build_product_research_pages.py
```

证据优先复用14天内缓存，接口异常即停止继续调用。原响应放在 `new_entrant_evidence/`，调用账本是 `new_entrant_collection.json`；过期重采前保存原响应到 `history/`，不删除。来源为空、失败或额度用尽保持待核，不能当负面市场结论。

`new_entrant_analysis.json` 是离线派生事实，不会自动完成因果分析。执行研究的智能体必须审读原始评论、变体和趋势，必要时核对品牌官方资料，写 `new_entrant_reviews.json`（主驱动、四维因素、证据、下一步及来源）。审核必须绑定原快照和 `evidence_digest`，14天后或证据更新需重审。只有有明确可复制性证据的人工/智能体审核才可标 `independent_entry_supported`，仍不能绕过利润、专利、季节性和合规核验。目标形态只有品牌/低价/共享链接样本时暂缓立项；其他形态独立判断。

分类修订先增加反例测试，再使用缓存重算。保留旧扫描和旧研究快照，禁止直接删除不再采用的证据。
